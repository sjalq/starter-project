# Working in this repository

Lamdera (Elm) application template. `.cursor/rules/lamdera.mdc` covers architecture and conventions; `.cursor/rules/elm-functions.mdc` indexes every function in `src/`. Where they disagree with this file, this file wins.

Reach `lamdera live` at `http://localhost:8000`, never `0.0.0.0`.

## Commands

```bash
./compile.sh                        # function index + tests + compile; run before calling anything done
elm-test-rs --compiler lamdera      # tests only (not elm-test: only elm-test-rs compiles Lamdera codecs)
npm run review                      # elm-review (npm install once)
./reset.sh                          # clears the compiler cache on Types.w3_encode_* errors
```

## Deploying (sjalq.app box)

This is the `lam` branch. Apps go live at `https://<name>.sjalq.app` via `lam deploy`, never lamdera.app. First deploy: `node scripts/node/new-app.js <name>` (needs `lam login`). After that: `./compile.sh`, commit, `lam deploy`. Production config: `lam api agentApply` `set_env`, then deploy (config-only: `git commit --allow-empty -m "Apply config"` first). Full steps in README "Live on the sjalq.app box"; account-level operations in <https://lmd.sjalq.app/llm_guide.md>.

## Laws

**MISI first.** Shape types so invalid states cannot be constructed; tests are the second line. When you catch a bug, first ask what type change makes that class of bug impossible.

**The why lives in the commit message.** Code says what; the commit that made a decision says what was chosen, what was rejected, and why. Before changing or undoing a rule, read its history (`git log -S'<identifier>'`, `git blame`). A decision with a stated reason is changed only with a stated reason.

**Types live in `Types.elm`, deliberately.** One domain module gives total pattern matches and no import cycles. A type moves out only when it is private to one module and moving it removes an import. Define each domain type once. Strengthen with opaque smart-constructed types, not by splitting the module.

**Parameter order: `fn model record`.**
1. A function that only reads the model takes it first; one that returns it takes it last, so it pipelines. Never in the middle.
2. Bundle adjacent same-typed params into a record so a swap is a compile error (`{ from : Email, to : Email }`).
3. Never pass unaltered copies of model fields; pass the key and look it up.
4. Single-use param records stay inline; promote to `Types.elm` on a second genuine user.

**DRY means same thing, not same shape.** Reuse and componentize a genuinely shared path (check `Supplemental.elm` and `Components/` first). Two sites that look alike but have different invariants or failure modes stay two functions.

**Answers over re-dispatch (a preference).** When a parent drives a child state machine and needs to know what happened, give it a named transition returning `( child, Answer, effects )` rather than a generic `update` plus a `_ ->` fallthrough.

**Hot paths never pay O(everything).** Frontend `view` runs after every update, `subscriptions` fire on every tick, and backend `updateFromFrontend` runs per message from every client. On those paths:
- Look up by `Dict` key; never scan a whole `BackendModel` collection per message.
- Build lists with `x :: acc` and one `List.reverse`, never `acc ++ [ x ]`; track membership in a `Set`, not `List.member` against the accumulator.
- Send deltas to the frontend, not the whole collection, when one item changed.
- `Html.Lazy` compares by reference: pass primitives or fields read straight off the model, never a freshly built record or list.

Cold paths (init, admin pages, migrations) may be O(n); do not optimize them at the cost of clarity.

**The BackendModel is the database; never destroy user data.** Evergreen migrations map every old field forward or document the loss in the commit. Handle recoverable failures by performing the corrective transition; show an error only when the case is terminal or needs a human.

**Facts and verbs in JS; decisions in Elm.** Code in `elm-pkg-js/` may gather facts and execute verbs (clipboard, storage, fetch). It never decides product behaviour: no classification, gating or policy in JS. Prefer a pure Elm package over a port.

**Generated and vendored files are not hand-edited.** `.cursor/rules/elm-functions.mdc` is regenerated by `./compile.sh`. `auth/` is vendored from lamdera/auth; change it only when the task is about auth.

**The compiler only sees Elm.** Before renaming or deleting a module or file, grep the whole repo: shell scripts, `compile.*`, `reset.*`, `elm-pkg-js-includes.js`, and CI YAML name files as strings.

**elm-review findings are real or fixed.** No suppression baseline. The ignored directories in `review/src/ReviewConfig.elm` are vendored code and Evergreen migrations only.

**The working tree is not yours alone.** Never run `git checkout -- <path>`, `git restore`, `git stash`, `git reset --hard` or `git clean` across paths you did not write, even to undo your own mistake; edit it back instead. Formatting is its own commit.

**Bounded adversarial review.** One review round on the plan if the feature merits it, one on the finished implementation, one fix pass for High and Medium findings, then focused compile and test checks. No recursive review loops.

## Tests

```
tests/Program/     End-to-end program tests (lamdera/program-test, Effect.Test)
tests/Property/    Property and unit tests for pure modules
tests/Fuzzers/     Shared fuzzers
tests/Helpers/     Helpers.Simulation config and test models
tests/TestViewer.elm  Visual snapshot viewer
```

Prefer property tests, then program tests, then unit tests. `elm-test-rs` discovers every exposed `Test`; do not add an aggregating `Tests.elm`. `tests` is a source directory, so test module names must not collide with app modules.

```elm
Sim.start "examples page shows the clipboard card"
    [ Test.connectFrontend 0
        (Effect.Lamdera.sessionIdFromString "session-1")
        "/examples"
        { width = 1920, height = 1080 }
        (\frontend ->
            [ frontend.checkView 100 (Query.has [ text "Clipboard Example" ])
            , frontend.update 100 ToggleDarkMode
            , frontend.portEvent 100 "clipboard_from_js" payload
            ]
        )
    , Test.checkBackend 100 (\backend -> Ok ())
    ]
    |> Test.toTest
```

Program tests only simulate `Effect.*`. Anything behind `Command.fromCmd` (raw `Lamdera.sendToBackend`, `Random.generate`) runs in the app but is silently skipped in tests, so use `Effect.Lamdera`, `Effect.Task`, `Effect.Time`, `Effect.Http`, `Effect.Command.sendToJs` and `Effect.Subscription.fromJs`.

Visual snapshots: `frontend.snapshotView 100 { name = "..." }` in `tests/TestViewer.elm`, then `./scripts/run-test-viewer.sh` and open <http://localhost:8888/viewer.html>.

## Wire protocol

`A String` (ToBackend) and `A0 String` (ToFrontend) must stay the alphabetically first constructors: the WebSocket client encodes them as tag 0 (`tests/Property/WebSocketWireTests.elm`).

## Permissions

Every `ToBackend` message passes `Backend.updateFromFrontendCheckingRights` → `Rights.Permissions.sessionCanPerformAction`. A new constructor goes into `Rights.Permissions.actionRoleMap` with its minimum role (`Anonymous`, `UserRole`, `SysAdmin`); the compiler points you there.

## RPC endpoints

Handlers live in `src/RPC.elm`, served at `/_r/{endpoint}`, registered in `lamdera_handleEndpoints`:

```
JSON:  SessionId -> BackendModel -> Headers -> Json.Value -> ( Result Http.Error Json.Value, BackendModel, Cmd BackendMsg )
Raw:   SessionId -> BackendModel -> HttpRequest -> ( RPCResult, BackendModel, Cmd msg )
```

Guard privileged endpoints with `RPC.isAuthorized request.headers` (checks `x-lamdera-model-key`; the dev key is refused in Production). Built-ins: `getModel`, `setModel`, `getLogs` (model key), and the async pair `getPrice` / `getPriceResult`. Work that outlasts the request timeout follows `EndpointExample/Price.elm`: `AsyncRPC.handleTaskChain`, return a token, poll with `AsyncRPC.handlePollingResult`.

Always send a JSON body:

```bash
curl -X POST "http://localhost:8000/_r/getLogs" \
  -H "Content-Type: application/json" -H "x-lamdera-model-key: 1234567890" -d '{}'
```

## Logs

Backend `Logger.logInfo` / `logWarn` / `logError` / `logDebug` write to `BackendModel.logState` (capped at `Env.logSize`, shown at `/admin/logs`, returned by `/_r/getLogs`) and to Lamdera's disk-backed log (`node scripts/node/lamdera-logs.mjs read --lines 100`, see `LAMDERA-LOGS.md`). Tail production over RPC with `node scripts/node/lamdera-cli/index.js logs --env prod --follow` (setup: `npm ci --prefix scripts/node/lamdera-cli`, copy `.lamdera-cli.example.json` to `.lamdera-cli.json`).

## REPL

With `lamdera live` running, click "Show Repl" in the dev bar. All tabs: `fem`, `setFem`, `updateFE`, `sendToBE`, `capture`. Leader tab only: `bem`, `setBem`, `updateBE`, `sendToFE`, `broadcast`. `fem`/`bem` are live; `capture bem` snapshots.

```elm
> bem.users |> Dict.keys
> updateFE ToggleDarkMode
> setBem { bem | pollingJobs = Dict.empty }
```

Shell: `lamdera backend --import='import Dict' --eval='Dict.size model.users'`.
